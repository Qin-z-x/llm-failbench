## Reproduction

From the repository root, with plain `python` (Python 3.9 or newer; CI exercises 3.11 and 3.13; no third-party dependencies):

```shell
python -m failbench validate --strict
python -m failbench run --provider mock --demo --out results/demo
python -m failbench report --results results/demo --out site
python -m failbench replay --results results/demo --out results/replay
```

The demo run writes `results/demo/results.json` and `results/demo/raw.jsonl`; the reported numbers come from `results.json` and the raw attempts are replayable offline. Two mock demo runs produce identical per-probe statuses, counts and response hashes; the run metadata (run_id, timestamps) differs by design, so compare the normalized per-probe results rather than the raw files.

## Run against your own endpoint

Any OpenAI-compatible `/chat/completions` endpoint works. API keys are read from an environment variable and never written to an artifact.

```shell
export FAILBENCH_BASE_URL="https://<your-host>/v1"
python -m failbench run --provider openai \
  --base-url "$FAILBENCH_BASE_URL" --api-key-env FAILBENCH_API_KEY \
  --model <model-name> --out results/run1
python -m failbench report --results results/run1 --out site
```

Local servers such as vLLM (`http://localhost:8000/v1`) or Ollama (`http://localhost:11434/v1`) use the same provider.

## CI gate

```shell
python -m failbench gate \
  --baseline results/baseline/results.json \
  --current results/candidate/results.json
```

The gate exits non-zero when a probe that passed in the baseline now fails or errors, or when a baseline probe is missing from the current run. It is a per-probe status comparison only: it does not compare aggregate scores, severity-weighted or otherwise. The offline mock provider keeps the gate testable in CI without an API key.

## Methodology and threats to validity

Probes are static prompts scored by mechanical rules (substring contains, exact match, regex, numeric tolerance, a minimal JSON-schema subset, or a conjunction of these). No LLM-as-judge is used. Errors are recorded separately and never counted as failures.

Threats to validity:

- Small per-class samples: one probe can move a class pass rate by several points.
- Static single-turn prompts only; this is not a general capability ranking.
- Public fixed corpus: overfitting is possible; add private probes for holdout.
- Mechanical grading favours checkable properties over open-ended quality.
- Results are specific to the committed prompts, parameters and endpoint snapshot.
- Evidence popularity is not severity or prevalence.
